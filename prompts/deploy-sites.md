# Deploy the Strava relay to ChatGPT Sites

Paste this prompt into ChatGPT Work with Sites available:

> @Sites Publish the Strava MCP gateway from the `main` branch of https://github.com/leecjohnny/strava-mcp-gateway. Reuse the selected or previously identified Site when updating or troubleshooting; do not create another Site because the repository template omits its project ID. Read `README.md`, `docs/setup.md`, and `prompts/deploy-sites.md`, then follow that file's requirements and procedure. Use the shared TypeScript Worker with public runtime configuration `MCP_PATH=/api/mcp` and the current official Sites hosting instructions. Verify the public deployment, then return the Site URL, exact MCP URL, and browser sign-in instructions.

## Requirements

- Use `worker.ts`, the same relay implementation used by Cloudflare and Vercel. Adapt only deployment packaging and public environment configuration.
- Keep the hosted relay stateless: no runtime application secrets, databases, token storage, server sessions, or background refresh. The authorization page keeps a login in browser memory for at most ten minutes. ChatGPT stores the upstream tokens and requests refresh through the relay.
- Preserve the browser-guided handoff: the user signs in to Strava in a separate tab, copies the full localhost callback address from that tab, then pastes it into the gateway page. Validate the exact callback and state before returning the original code, state, and issuer to ChatGPT. No local installation or service is required; do not claim this manual step is automatic.
- Strava must receive exactly `http://localhost:61847/callback` as `redirect_uri` in authorization and code exchange. A hosted relay URL or ChatGPT callback must never replace it.
- Publish for **Anyone on the internet**. Discovery and the MCP endpoint must be reachable without a Sites or ChatGPT sign-in gate. Strava credentials still control access to account data.
- Preserve OAuth request parameters, the exact PKCE challenge/verifier, raw token forwarding, and incremental MCP streaming. The owner has accepted the transparent relay's lack of gateway-specific token audience isolation.
- Keep one deployment's exact public origin consistent in discovery and OAuth responses. Use the external request origin when the runtime preserves it; otherwise configure the public, non-secret `PUBLIC_ORIGIN` using the Site's returned URL.
- Set the public runtime variable `MCP_PATH=/api/mcp` using supported hosting configuration before packaging and publication. The tested Site intercepts `/mcp`; `/api/mcp` reaches the Worker. Keep the configured resource consistent in discovery, authorization, and token requests. This is a locally tested candidate that still requires hosted verification.
- Preserve the MIT license and README disclaimer: this is an unofficial workaround for Strava users who do not use Claude, with no affiliation or endorsement from Strava, ChatGPT (OpenAI), Cloudflare, or Vercel.

## Procedure

1. Read the current official [Sites documentation](https://learn.chatgpt.com/docs/sites), available Sites hosting skill, and `.openai/hosting.json`. When updating or troubleshooting, reuse the selected or previously identified Site and recover its `project_id` from Sites if the repository template omits it. A missing template ID is not permission to create another Site. Provision once only for an explicitly new Site. Preserve the selected ID and other manifest fields.
2. Confirm the supported Worker entrypoint, archive layout, request routing, and compatibility settings from those instructions. Cloudflare's `wrangler.jsonc` does not establish Sites' runtime flags. Do not invent manifest fields or assume that enabling Node compatibility supplies every Node API. The hosted relay uses standard Fetch APIs and does not need a Node HTTP listener.
3. Install the locked dependencies with `npm ci`, run `npm run check`, and run `npm run build:sites`. Browser assets build automatically through `prepare` and Wrangler's custom build step. The Sites build produces a local Worker candidate; it does not validate the final Sites archive or publish anything.
4. Package the build using the Sites hosting skill's supported helper. Include the valid hosting manifest and compiled Worker output with its authorization page. Exclude source secrets, local environment files, and development artifacts. If the required skill or archive contract is unavailable, report what remains unverified instead of presenting the candidate as a validated Sites deployment.
5. Use the Sites source-repository workflow to push the exact source state for the version. After a successful push, obtain the full commit SHA with `git rev-parse --verify HEAD`. Save a version built from that source state, then publish that saved version with the required public audience. Follow any narrower instruction from the user, including local-only work or saving without publication.
6. Verify anonymous access to `/`, browser assets, OAuth discovery, and `/.well-known/oauth-protected-resource/api/mcp`. Both protected-resource metadata endpoints must advertise `https://THE-SITE-ORIGIN/api/mcp`. Anonymous `GET`, `POST`, and `DELETE` requests to `/api/mcp` must return the relay's `401` and resource-metadata challenge, not a Sites-generated `404` or hosting login page. Verify the selected origin, OAuth issuer, and exact localhost callback. Do not declare hosted routing fixed until these checks pass.
7. For live account linking, have the user start OAuth from ChatGPT, sign in to Strava through the gateway page, and copy the full localhost callback address into that page. Verify completion in ChatGPT, token refresh, and authenticated streaming when the user can authorize it. Confirm localhost is still the upstream redirect during code exchange. Report simulated tests separately from a real account connection; a successful build or initial redirect validation does not prove live linking works.

Native Sites MCP registration is separate from this application route. Sites may still report “The published Site does not declare an MCP server.” Do not invent enablement fields or claim this candidate resolves native registration. If public endpoint checks pass, the user can manually add the exact MCP URL as a custom server in ChatGPT; live account linking remains a separate check.

Return the Site URL, the exact configured MCP URL (normally `https://THE-SITE-ORIGIN/api/mcp`), saved version, verification results, and any remaining limitation. Do not add GitHub Actions or another CI workflow.
